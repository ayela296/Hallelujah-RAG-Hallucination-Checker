Welcome to the repo! To keep our code clean and avoid breaking things while working together, we follow a simple branching strategy:

Branching Rules & Workflow
main: This is our production-ready branch. Do not commit directly to main—it should only contain final, stable code.

dev: Our main working branch where everyone's code comes together. All active development happens here first.

feature/<feature-name>: Whenever you start working on a new task or ticket, create a separate feature branch off dev (e.g., feature/api-setup).

Pull Requests: Never push straight to dev or main. Once your feature is ready, open a Pull Request (PR) to dev so another team member can review your changes before merging.
